  "GET /produits.php?id=..."   requête reçue, avec la charge SQL dans le paramètre id

Décodage de l'URL :
  %20 = espace      %27 = '      %3D = =      %28 = (      %29 = )

Exemple : id=1%20UNION%20SELECT%20null,null--
  devient : id=1 UNION SELECT null,null--

Remarque : la page répond 200 même pour une attaque. Le serveur ne rejette
pas la requête, c'est justement pourquoi la détection par Snort est utile.

4. COMPTAGES
--------------------------------------------------------------------------

Alertes SQLI dans snort.alert.fast ............ 583
Lignes SQLI dans syslog-ng-central.log ........ 586
Documents Kibana (message : *SQLI*) ........... 588

Pourquoi plus de lignes que d'alertes : le mot SQLI apparait aussi dans les
commandes sudo tapées pendant les vérifications (par exemple
sudo grep -c "SQLI" ...). Elles sont tracées dans auth.log, donc collectées
par syslog-ng et envoyées à Kibana avec program = sudo (3 lignes de plus
dans syslog-ng-central.log, 5 de plus dans Kibana au moment de la capture).
Elles se filtrent avec :
  message : *SQLI* and not program : "sudo"
